# Experiment log (Nov 19, 2026, evening)

No Anthropic API key was available, so these experiments cover everything that runs offline: the free keyword extractor (the fallback and the baseline), privacy, robustness, load, SMS cost and the UI. The AI comparison is set up and ready: `python -m eval.ai_sweep`.

## Setup
- `eval/dev.jsonl`: the original 30 labelled notes. **Rules were tuned on these only.**
- `eval/test.jsonl`: 30 new labelled notes written *before* any tuning. Held out.
- `eval/voice.jsonl`: test set rewritten the way phone dictation writes (numbers as words, no punctuation), generated by `eval/make_voice_set.py`.
- Score = share of 6 fields right (activity type, people, youth, neighborhood, referred-to orgs, outcome).

## 1. Keyword extractor v1 → v2 (`app/rules.py`)
| Version | Dev (tuned on) | **Test (held out)** | Voice-style |
|---|---|---|---|
| v1 (first version) | 60.0% | **65.0%** | not measured |
| v2 | 95.6% | **90.6%** | 75.0% |
| v2 + "hot dogs" fix* | 95.6% | **91.1%** | 75.0% |
| v2 + number words ("twenty kids") | 95.6% | **91.1%** | **91.1%** |

\*Found on the test set, so 91.1% is slightly optimistic; 90.6% is the clean held-out number.

What changed in v2: add up every "N people/kids/coats" group, handle "N of them kids" and "family of 5", skip ages, times and street numbers; strong signals (pets, de-escalation) decide the activity, else the first-mentioned activity wins; outcome from future/waiting/finished wording; an org after "w/" or "met with" is a partner, otherwise a referral.

Still weak (test set): outcome when a note has no verb ("winter coat giveaway, 85 coats") at 73%; people count at 80%. These are what the AI should fix. Run the AI comparison to confirm.

## 2. Privacy
**Found:** the full note was stored as typed, and without AI the summary *was* the raw note, so a phone number or "Ms. Johnson at 2411 N 35th St" would show on the dashboard and could be quoted in the report. The README claimed names were never stored.
**Fixed:** `app/privacy.py` scrubs phone numbers, emails, street addresses and titled names ("Ms. Johnson", "mrs smith") **before** a note is stored or sent to Claude. The report only quotes AI-written summaries. Limit: a bare first name ("took Tanya to court") isn't caught offline; the AI summary removes it, but the stored raw note keeps it.

## 3. Robustness (`python -m eval.robustness`, 56 checks)
Empty, blank, emoji, XML/HTML/SQL injection, prompt injection, 2M-person typo, 2,500-char note, odd Unicode, bad edit values, missing SMS fields, weird date ranges.
**Found and fixed:** the edit endpoint accepted `outcome: "lol"` and `people_served: -4`; a note of only spaces was saved as an empty record; SMS had no length limit; no upper bound on people counts. **Now 56/56 pass.**

## 4. Duplicates
**Found:** a text sent twice (bad signal) or a double-tapped Save counted twice, inflating people served. **Fixed:** the same words from the same person within 10 minutes are recognized ("Already got that one (#12)").

## 5. Report accuracy
Report totals (entries, people, youth, referrals) match a direct SQL count exactly.

## 6. Load (`python -m eval.load_test`, keyword mode, laptop)

Dashboard at **50,000 entries**: month view 0.14 s, full year 1.8 s, CSV export 1.1 s. **Found:** totals silently stopped counting after 5,000 entries in the selected period. Fixed; added a date index.

## 7. SMS cost (`python -m eval.sms_cost`)
Twilio bills per segment: 160 chars for plain text, but only **70** if any character outside the basic SMS alphabet appears ("·", "→", 🙏).
| | Avg segments per reply | Replies that fit in 1 segment |
|---|---|---|
| Before | 2.05 | 8 / 64 |
| After (plain characters, shorter wording) | **1.00** | **64 / 64** |
That roughly halves outbound texting cost. Also fixed "1 people" → "1 person".

## 8. Browser click-through (`python -m eval.browser_test`)
Real headless Edge: name step → type → Save → confirmation → Undo (restores text, deletes entry) → name remembered → dashboard Done → period filter → report → phone simulator → no sideways scroll at 420px → no JS errors. **14/14 pass.**

## 9. AI plumbing (checked with a fake client)
Requests carry structured output + `effort`; Opus/Sonnet get the refusal fallback; **Haiku doesn't** (it has none and would have rejected the parameter, silently dropping every note to keywords). Network errors and refusals fall back to keywords and are now counted at `/api/health`. `max_tokens` raised from 2,000 to 16,000 because thinking tokens count against it, so a long think could have cut off the JSON. Requirements now pin `anthropic>=2.11`, the version tested.
